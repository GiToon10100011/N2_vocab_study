# 실전 테스트 (한자 → 읽기 타이핑) — 설계

작성 2026-10-22 (N2_Orchestration ORCHESTRATOR) · 상태: **승인됨 (2026-10-22)**

표시 규칙: **(사용자)** = 사용자가 정한 것. **(판단)** = ORCHESTRATOR가 정해 사용자에게 말한 것 — 사용자가 뒤집을 수 있다.
아무 표시가 없는 것은 기존 규칙(CLAUDE.md)이나 코드에서 따라 나온 것이다.

---

## 1. 왜 만드나

플래시카드의 「한자 → 읽기」(s2r)는 **자기 채점**이다. 사용자의 말:

> 현재 단어를 무슨 뜻인지 알아보는건 얼추되지만, 정확한 발음을 몰라 헷갈리는 경우가 있는데도
> 그냥 뜻이나 단어 자체를 아니까 안다고 흐지부지 넘어가는 제자신을 볼 수 있어 이대론 안될 것 같습니다.

실제로 헷갈리는 것은 しょう / そう / ちょう 같은 요음과 **장음이 붙는지 여부**다.
예: 抽象的(ちゅうしょうてき)을 「ちゅうそうてき」로 기억하고 있었다.

뜻을 알면 「알았음」을 누르게 되므로, 플래시카드만으로는 흐릿한 읽기가 드러나지 않는다.
**직접 쳐서 글자 단위로 채점하면 흐릿한 읽기가 드러난다.** 드러난 단어는 플래시카드로 되돌린다.

## 2. 목표 · 비목표 · 안티목표

### 목표

- 한자(표기)를 보고 읽기를 가나로 직접 친다. 글자 단위로 엄격하게 채점한다.
- 틀리면 어느 음절이 틀렸는지 나란히 보여 준다.
- 틀린 단어는 플래시카드 SRS로 되돌린다.
- 이틀에 한 번, 매일 복습과는 따로 뜬다.
- 이미 등록된 단어(약 290개)를 위험도 가중으로 섞어 한 바퀴 돈다.

### 비목표 (v1에서 하지 않는다)

- 혼동 유형 통계(しょう/そう 류 집계). 나중에 할 수 있도록 **데이터만 남긴다**(§4.7).
- 뜻 테스트 · 읽기 → 뜻 · 뜻 → 읽기 (CLAUDE.md 절대 규칙 2).
- 한자 쓰기 (절대 규칙 1).
- 테스트 주기 설정. 이틀로 고정한다 **(판단)**.

### 안티목표 — 기술적으로 돌아가도 이렇게 되면 실패다

- **자기 판정 구멍.** 「오타였음」 버튼, 되돌리기, 채점 뒤 정답 인정 같은 것. 플래시카드의 문제를 그대로 옮겨 온다. **(사용자: 「오타였음은 두지말자」)**
- **잘린 읽기로 채점.** 부분 변환으로 `ふきゅう`가 `ふきゅ`로 잘리면, 아는 단어가 오답 처리되고 단계가 떨어진다 (절대 규칙 6과 같은 사고).
- **장음 오류를 정답 처리.** 가타카나 `ー`를 모음으로 바꾸면 `チューショーテキ`가 정답이 된다 (§4.4).
- **테스트가 밀려 쌓임.** 공부 못 한 날 다음 날 두 배가 되는 일은 이 프로젝트가 피하는 것이다.
- **오답이 한꺼번에 몰림.** 가장 어려운 단어만 모아 한 번에 내면, 다음 날 플래시카드가 폭증한다.
- **테스트 기록이 플래시카드 복습으로 섞임.** 홈 통계와 외부 집계(§4.7)에서 둘을 구분할 수 있어야 한다.

## 3. 사용자가 정한 것

| 항목 | 결정 |
|---|---|
| 형식 | 한자를 보여 주고 읽기를 가나로 친다 |
| 채점 | 한 글자라도 다르면 오답. 장음 · 요음 · 촉음 포함 |
| 오답 표시 | 음절 단위 대조 — `ちゅう[そう]てき` ↔ `ちゅう[しょう]てき` |
| 오답의 SRS 반영 | **플래시카드도 같이 내려간다** — 「몰랐음」과 같다 (stage 1, 내일) |
| 주기 | 이틀에 한 번. 매일 SRS와 별개 |
| 기존 단어 | 위험한 것 우선. 단 **문제는 섞어서** 낸다 (플래시카드처럼) |
| 분량 | 한 번에 20분을 넘기지 않는다. 40문제 정도 |
| 입력 | 일본어 키보드(아이폰 플릭 · PC IME)와 로마자 **둘 다** |
| 오타 | 「오타였음」 버튼을 두지 않는다 |
| 순서 | 몇 주짜리 장기 공백이 오기 전에는 기존 단어 한 바퀴가 먼저다. 새 단어 테스트가 대부분 그 뒤로 밀려도 괜찮다 |

## 4. 동작

### 4.1 언제 뜨나

- 홈에 매일 복습과 나란히 「실전 테스트」 카드가 뜬다.
- 마지막으로 **끝낸** 테스트의 학습일로부터 2일 이상 지난 학습일에 뜬다. 날짜를 고정하지 않는다 **(판단)**.
  - 그래서 주말이나 긴 공백 동안 쌓이지 않는다. 몇 번을 건너뛰어도 뜨는 것은 **항상 1회분**이다.
  - 테스트 기록이 없으면(첫 테스트) 바로 뜬다.
  - 하루 경계는 04:00(`studyDate()`)이다.
- 낼 수 있는 단어가 0개면 뜨지 않는다.
- 기한 전에 미리 보는 버튼은 두지 않는다 **(판단 — 사용자에게 아직 확인하지 않음)**. 추가 연습은 기존 연습 퀴즈가 맡는다.

### 4.2 어떤 단어가 나오나

**대상:** 표기에 한자가 있는 단어(`isKanaOnly` 제외), `suspended` 아님, 이미 학습한 단어.
**그날 처음 배운 단어는 제외**한다 **(판단)**.

**문제 수:** N. 기본 40이고 설정에서 바꿀 수 있다 **(판단 — 사용자가 「40 정도」라고 했고 확신은 없었다)**.
처음 2~3번 실제로 걸린 시간을 보고 사용자가 조정한다.

N 자리를 이 순서로 채운다.

1. **재시험.** 테스트에서 틀린 뒤 아직 테스트에서 **두 번 연속** 맞히지 못한 단어. 이 단어들이 N을 넘으면 오래 기다린 것부터 넣는다.
2. **처음 보는 단어.** 남은 자리는 테스트에 한 번도 안 나온 단어로, **가중 무작위**로 채운다. 아래 조건일수록 뽑힐 확률을 높인다.
   - 플래시카드 s2r 오답 이력이 있다 (횟수가 많을수록)
   - 읽기에 헷갈리는 소리가 있다 — 요음(ゃゅょ), 장음(おう · えい · ゅう 류), 촉음(っ)
   - 오래된 단어다 (학습일이 이르거나 단계가 높다)

   「오래된 단어」 가중 덕분에 장기 공백 전에는 기존 단어가 새 단어보다 먼저 돈다.
   이 규칙은 공백이 끝난 뒤에도 따로 손대지 않고 그대로 쓴다.
   **위험한 것부터 순서대로 넣지 않는다.** 그렇게 하면 첫 테스트가 가장 어려운 단어로만 채워져 오답이 몰린다(§2 안티목표).
3. **한 바퀴를 다 돈 뒤.** 모든 대상 단어가 테스트를 통과했으면, 남은 자리는 통과한 지 가장 오래된 단어로 채운다 **(판단)**.
   후보가 N보다 적으면 그만큼 짧은 테스트가 된다.

**문제 순서는 매번 섞는다** (`shuffle`).

### 4.3 화면 흐름

- 한 문제에 표기(한자)만 보인다. **정답 읽기와 뜻은 답을 내기 전까지 DOM에 렌더하지 않는다** (절대 규칙 3과 같은 취지).
- 입력칸은 하나다. 입력칸 아래에 「이렇게 채점된다」는 가나 미리보기를 둔다(§4.4). 사용자는 이 미리보기를 보고 오타를 잡는다.
- 제출은 Enter 또는 버튼이다. 제출 뒤에는 맞음/틀림, 정답 읽기, 뜻을 보여 주고, 틀렸으면 음절 대조를 보여 준다. 그다음 문제로 넘어간다.
- **같은 테스트 안에서 틀린 단어를 다시 묻지 않는다 (판단).** 정답을 본 직후에 맞히는 것은 기억이 아니라 잔상이다 (기획 5.3과 같은 이유). 그 단어는 다음 테스트에 다시 나온다.
- 끝 화면에는 맞힌 수와 틀린 단어 목록(대조 포함)을 보여 준다.
- **되돌리기는 없다.**

### 4.4 입력과 정규화

사용자는 두 방식 모두 쓴다. 전환 버튼 없이 입력칸 하나에서 받는다.

- **일본어 키보드(플릭 · IME):** 가나가 그대로 들어온다.
- **로마자:** 입력칸은 **친 그대로** 둔다. 미리보기 줄에 문자열 전체를 변환한 결과를 보여 준다.
  - 입력칸 내용을 바꿔 쓰는 부분 변환(wanakana IMEMode · bind)은 **쓰지 않는다** (절대 규칙 6).
    이미 같은 패턴이 있다. `app/study/StudySession.tsx` 단어 수정 대화상자의 읽기 칸과 `→ {readingKana}` 줄이다.
  - 사용자에게는 「치는 동안 가나로 바뀌어 보인다」고 설명했다. 이 미리보기 줄로 그 설명을 충족한다.
  - IME 관례 `nn`(しんぶん = `shinbunn`)은 `lib/kana.ts`의 `fromImeRomaji`와 같이 처리한다.
    대문자는 소문자로 바꾼다 (`normalizeReading`이 이미 그렇게 한다).
  - 로마자 `-`는 `ー`가 된다. 그대로 두면 장음 오답이 된다.
- **가타카나 입력:** 히라가나로 바꿔 비교한다. **단 `ー`는 보존한다.** `ちゅー` ≠ `ちゅう`.
  - **`wanakana.toHiragana`를 이 비교에 쓰지 말 것.** wanakana는 `ー`를 앞 모음으로 바꾼다.
    2026-10-21에 wanakana 5.3.1에서 확인했다: `toHiragana('チューショーテキ')` = `'ちゅうしょうてき'`, `toHiragana('ソー')` = `'そう'`.
    대신 코드포인트를 옮겨 바꾼다(ァ-ヶ → ぁ-ゖ).
- **한자가 섞인 입력**(IME에서 실수로 변환한 경우)과 **가나가 아닌 문자가 남은 입력**은 채점하지 않는다.
  「가나로 다시 입력」 안내를 띄우고 같은 문제에 머문다.
- 공백은 지운다.
- **な형용사 끝의 `だ`:** 정답 읽기와 표기가 둘 다 `だ`로 끝나면, 입력에 `だ`가 있든 없든 정답으로 친다 **(판단)**. 단어장 표기 관례일 뿐 읽기 지식이 아니다.
- **IME 확정 Enter는 제출이 아니다.** `isComposing`, 조합 중 플래그, `keyCode === 229`를 모두 거른다.
  Safari는 확정 Enter를 `compositionend` 뒤에 보낸다. 같은 처리가 이미 `app/mistakes/new/MistakeForm.tsx`에 있다.
  IME 조합 내용을 가로채거나 고치지 않는다.
- 입력칸에 `lang="ja"`, `autoCapitalize="none"`, `autoCorrect="off"`, `autoComplete="off"`, `spellCheck={false}`를 준다.
  자동 수정이 답을 바꾸면 안 된다.
- 정답 읽기는 단어당 하나다(DB `reading`). 2026-10-21 기준으로 여러 읽기를 구분자로 넣은 행은 없다.

### 4.5 채점 결과의 반영

| 결과 | stage · next_review | 카운터 (correct_count · wrong_count · streak · last_wrong_type) |
|---|---|---|
| 정답 | **그대로** | 갱신한다 (연습 퀴즈와 같이) |
| 오답 | **stage 1, 내일** (`gradeSchedule(state, false, today)`) | 갱신한다. `last_wrong_type = 's2r'` |

- 정답일 때 단계를 올리지 않는 이유 **(판단)**: 테스트는 읽기를 확인하는 자리다. 올리면 같은 날 플래시카드와 테스트에서 두 번 오를 수 있다.
- 오답일 때 `last_wrong_type = 's2r'`이므로 다음 날 플래시카드는 그 단어를 s2r로 낸다 (`pickPromptType` 규칙 1). 이건 의도한 동작이다.
- SRS 계산은 서버에서만 한다 (`lib/srs.ts` 단일 출처 · `planGrades` 확장).
  정답 비교(정규화 + 비교)는 **순수 함수 하나**로 `lib/`에 둔다. 화면의 즉시 판정과 서버가 같은 함수를 쓴다.
  문제마다 네트워크 왕복을 넣지 않는다.
- **같은 날 플래시카드와 겹칠 때:** 테스트 오답이 그날 다시 뒤집히면 안 된다.
  - 테스트를 먼저 보면 단어의 `next_review`가 내일로 바뀐다. 그 뒤 새로 받은 플래시카드 큐에는 그 단어가 없다. 문제없다.
  - 문제는 플래시카드 세션을 열어 둔 채로 테스트를 보고 돌아오는 경우다. 열어 둔 큐에 그 단어가 남아 있다가 맞히면 단계가 다시 오른다.
  - 막는 방법이 간단하면 막고, 아니면 알려진 한계로 문서에 남긴다.

### 4.6 「읽기 주의」 표시 **(판단)**

- 테스트에서 틀린 단어는 플래시카드 카드면에 「읽기 주의」를 표시한다.
- 테스트에서 두 번 연속 맞히면 사라진다. §4.2의 재시험 종료 조건과 같다.

### 4.7 기록

- `reviews.prompt_type`은 **`'s2r'`** 로 남긴다. **enum을 늘리지 않는다** (절대 규칙 2). 테스트임을 구분하는 표시는 따로 둔다.
- **테스트는 연습 퀴즈와도, 플래시카드 복습과도 다른 범주다.**
  - 홈의 「최근 7일 복습 · 정답률」과 `/stats` 유형별 집계에 테스트 기록이 플래시카드 복습으로 섞이면 안 된다.
- **외부 집계:** N2_Orchestration은 SRS DB를 읽기 전용으로 조회한다. 그쪽은 지금 `practice = false`를 「SRS 복습」으로 센다.
  두 가지 중 하나를 고르고 문서에 남긴다.
  - 테스트 행이 그 조건에 걸리지 않게 한다.
  - 테스트 행이 걸리는 것을 감수하고, 구분하는 열을 명시해 오케스트레이션 쪽 조회를 고치게 한다. 고치는 것은 ORCHESTRATOR 몫이다.
- **틀린 답으로 친 가나를 남긴다 (판단).** 나중에 혼동 유형 통계를 만들 때 쓴다.
  - 이 입력값은 **공개 백업(`backups/`)에 넣지 않는다.** `scripts/backup-tables.mjs`의 원칙 「공개 저장소에 새 종류의 기록을 올리지 않는다」를 따른다.
  - 테스트의 정오 기록 자체는 SRS 상태를 바꾸므로, 지금처럼 `reviews` 백업에 들어가야 복원할 수 있다.
- 테스트 상태(마지막으로 끝낸 테스트의 학습일, 단어별 테스트 연속 정답, 테스트 통과 여부)는 `reviews` 로그에서 끌어낼 수도 있고, 따로 저장할 수도 있다. 빌더가 정한다.

### 4.8 중단과 재개

- 중간에 나가도 **이미 낸 답은 잃지 않는다.** 서버가 `ok`라고 답한 뒤에만 기기 저장소에서 지운다 (기존 grade-outbox 원칙). 같은 묶음이 다시 와도 한 번만 반영한다.
- 같은 학습일에 다시 들어오면 남은 문제를 이어서 본다. N문제를 다 풀어야 「끝낸 테스트」가 되고, 다음 기한 계산은 이것을 기준으로 한다.
- 다 못 풀고 날이 바뀌었을 때 어떻게 할지는 빌더가 정한다. 단 「테스트가 쌓이지 않는다」(§4.1)는 지킨다.

### 4.9 설정

- 「실전 테스트 문제 수」 — 기본 40. 범위는 빌더가 정한다 (예: 10~100).
- 주기는 설정에 넣지 않는다 (§2 비목표).

## 5. 제약

- `CLAUDE.md` 절대 규칙 1~8 전부. 특히 2(enum), 3(DOM 누출), 6(부분 변환 금지), 8(학습 효과 없는 기능 금지).
- `lib/srs.ts`를 고치면 `npm test`가 통과해야 한다.
- 세션 중 네트워크 왕복을 늘리지 않는다. 채점은 서버 `ok` 뒤에만 지운다. 탭을 닫는 순간에는 보내지 않는다.
- **스키마 변경을 운영 DB에 적용하는 것(`npm run db:migrate`)은 사용자가 명시적으로 승인한 뒤에만 한다.**
  격리 DB에 먼저 올리는 방법은 `CLAUDE.md`에 있다. 코드가 스키마보다 먼저 올라가도 기존 화면이 죽지 않게 한다 (`fetchSettings`의 `to_jsonb` 패턴과 같은 취지).
- `npm run test:db`를 운영 DB에 돌리지 않는다. 통합 테스트 픽스처는 `ＺＺ` 네임스페이스를 쓴다 (규칙 7).
- 날짜는 `'YYYY-MM-DD'` 문자열이고 `studyDate()`를 쓴다.
- 저장소는 공개다. 개인 정보를 커밋하지 않는다.
- 커밋 메시지와 PR 설명에 attribution 줄이나 세션 URL을 넣지 않는다.
- **아이폰 실기기에서 확인하지 않은 동작을 「검증 완료」라고 보고하지 않는다** (§6).

## 6. 완료 확인

**단위 테스트 (순수 함수)**

- 정규화:
  - `ー` 보존 (`チュー` → `ちゅー`, ≠ `ちゅう`)
  - `nn` 처리, 대문자, 공백
  - 한자가 섞인 입력 거부, 로마자가 남은 입력 거부
  - 끝 `だ`
- 음절 대조: 요음은 한 음절로 본다. 장음 유무, 촉음 유무
- 출제 선택:
  - 재시험 우선, N 상한
  - 가중 무작위 (주입한 난수로 결정적으로)
  - 그날 배운 단어 제외, 가나 전용 단어 제외
  - 섞기
- 출현 판정:
  - 2일 조건, 04:00 경계
  - 여러 번 건너뛰어도 1회분
  - 첫 테스트, 대상 0개
- 채점 반영: 오답 → stage 1 · 내일 · `last_wrong_type = 's2r'`, 정답 → stage와 next_review 그대로

**E2E (격리 DB)**

- 테스트 한 번을 끝까지 본다
- 중간에 나갔다가 이어서 본다
- 오답 단어가 다음 날 플래시카드 큐에 s2r로 나온다

**아이폰 실기기 (사용자 확인 — 그 전에는 「미확인」으로 보고)**

- 플릭으로 가나를 입력한다. 확정 Enter가 제출되지 않는다
- 로마자를 치면 미리보기가 보인다
- 자동 수정과 자동 대문자가 꺼져 있다

## 7. 빌더에게 맡기는 것

- 스키마: 열 · 테이블 이름, 테스트 상태를 어떻게 저장할지, 오답 입력값을 어디에 둘지 (§4.7 제약 안에서)

- 날이 바뀐 미완료 테스트 처리 (§4.8)
